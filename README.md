# 工地危害巡檢記錄系統（HazardCheck）

> 全端網站開發實務 · **作業二：Web App（解決特定問題）**
> 作者：楊恒煦

---

## 解決的問題

工地安衛巡檢長期以**紙本**進行，實務上有四個痛點：

1. 現場填完的紙本要回辦公室才能整理，**當天的缺失常常隔天才建檔**
2. 缺失改善**難以追蹤**，誰在什麼期限前該改哪一項，散落在不同表單與群組訊息
3. 跨工地的缺失**無法彙整統計**，管理層看不到整體風險趨勢
4. 手寫字跡與照片對不上，事後回溯困難

## 使用對象

- **工地安衛人員**：現場用手機記錄缺失，不必帶紙本
- **工地主任／職安衛主管**：即時看到待改善件數與高風險件數
- **管理層**：跨工地彙整（本版本先做到單一資料表彙整統計）

## 這個版本做了什麼

| 功能 | 說明 |
|---|---|
| 現場填寫 | 手機優先的單欄表單，7 個欄位、12 種檢查項目 |
| 即時落地 | 送出後即寫入 Google Sheets，不需人工整理 |
| 統計 | 總記錄數、待改善件數、高嚴重度未改善件數 |
| 最近記錄 | 讀回最近 20 筆，依時間由新到舊，嚴重度以顏色區分 |
| 錯誤處理 | 必填驗證、長度上限、後端異常、網路失敗都有明確提示，失敗時不清空已填內容 |

## 架構

```
┌──────────────────────┐
│  手機 / 電腦瀏覽器     │
│  原生 HTML + CSS + JS │  ← 部署於 GitHub Pages
└──────────┬───────────┘
           │ POST（text/plain）／ GET（?action=list|info）
┌──────────▼───────────┐
│ Google Apps Script    │  ← 免費、公開、不需自架伺服器
└──────────┬───────────┘
           │
┌──────────▼───────────┐
│ Google Sheets（Sheet1）│  ← 資料真實落地
└──────────────────────┘
```

**為什麼不用框架**：對照第 03 講，這個規模（表單 + 列表 + 統計）用原生三件套
比引入框架更小、更快、更容易維護，也與本人履歷網站的技術路線一致。

## 本機執行

```powershell
# 任一靜態伺服器都可以（不要直接雙擊 index.html，fetch 會受 file:// 限制）
python -m http.server 8200
# 開 http://127.0.0.1:8200/
```

後端網址設定在 `app.js` 最上方的 `CONFIG.endpoint`。

## 後端測試（不需網路）

```powershell
node gas/_test_harness.cjs gas/Code.gs
```

用假的 `SpreadsheetApp` / `PropertiesService` 模擬 GAS 環境，
驗證驗證邏輯、錯誤處理、統計、排序與日期欄位正規化，共 31 項。

## 部署

### 後端（Google Apps Script）

1. 開 <https://script.google.com> → 新增專案
2. 貼上 `gas/Code.gs` 全文 → 儲存
3. 部署 → 新增部署作業 → 類型「網頁應用程式」
4. **執行身分：我**　**誰可以存取：任何人**
5. 授權後取得 `/exec` 網址 → 填進 `app.js` 的 `CONFIG.endpoint`

> 第一次被呼叫時會**自動建立** Google 試算表與表頭，不需手動開表。

⚠️ 修改程式後必須「部署 → **管理部署作業** → 編輯 → 版本選『新版本』→ 部署」才會生效；
只按儲存不會更新線上版本。

### 前端（GitHub Pages）

Settings → Pages → Source 選 **Deploy from a branch** → `main` / `/ (root)`。

## 資料表結構（Sheet1）

| 欄 | 表頭 | 說明 |
|---|---|---|
| A | timestamp | 伺服器寫入時間（`yyyy-MM-dd HH:mm:ss`，文字格式） |
| B | site | 工地名稱 |
| C | area | 區域／樓層 |
| D | item | 檢查項目 |
| E | severity | 高 / 中 / 低 |
| F | desc | 缺失描述 |
| G | dueDate | 改善期限（`YYYY-MM-DD`，可空） |
| H | inspector | 巡檢人 |
| I | status | 待改善 / 已改善（直接在 Sheets 改） |

詳見 `spec/02-api.md`。

## 已知限制

| 限制 | 說明 |
|---|---|
| **無身分驗證** | 知道網址的人都能寫入。僅供課程作業展示，**請勿填入真實工地敏感資訊** |
| 無照片上傳 | 真實巡檢常需要照片佐證，列為未來延伸 |
| 無後台管理介面 | 修改／刪除記錄請直接在 Google Sheets 操作 |
| 單一工地彙整 | 尚未做多工地權限分離 |
| GAS 的 CORS 限制 | POST 轉址後的回應可能讀不到，前端改用「送出後比對筆數」佐證成功 |
