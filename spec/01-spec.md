# 規格｜工地危害巡檢記錄系統（HazardCheck）

> **作業**：全端網站開發實務 作業二 Web App（解決特定問題）
> **建立日期**：2026-10-28
> **狀態**：已實作並通過 A1～A10 全部驗收（2026-10-28）

---

## 一、目標

讓工地安衛人員在**現場用手機**記錄危害巡檢結果，資料即時寫入 Google Sheets，
並可立刻看到當日／本月的缺失統計，取代紙本巡檢表。

---

## 二、範圍

### 本次包含

| # | 功能 |
|---|---|

## 三、輸入與輸出

### 單筆巡檢記錄的欄位

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `site` | 字串 | ✅ | 工地／專案名稱（≤ 50 字） |
| `area` | 字串 | ✅ | 區域／樓層／位置（≤ 50 字） |
| `item` | 字串（選單） | ✅ | 檢查項目，見下方清單 |
| `severity` | 列舉 | ✅ | `高` / `中` / `低` |
| `desc` | 字串 | ✅ | 缺失描述（≤ 500 字） |
| `dueDate` | 日期 | ⬜ | 改善期限（`YYYY-MM-DD`，可空） |
| `inspector` | 字串 | ✅ | 巡檢人（≤ 30 字） |

### 檢查項目清單（草案，**待你確認／增修**）

1. 墜落／開口防護
2. 施工架與支撐
3. 感電與臨時用電
4. 物體飛落／堆置
5. 機械設備與防護罩
6. 火災爆炸（易燃物、動火作業）
7. 缺氧／中毒（局限空間）
8. 個人防護具（PPE）
9. 警示標示與圍籬
10. 交通與動線
11. 環境衛生
12. 其他

### 輸出（API 回應）

| 動作 | 回應 |
|---|---|
| 新增記錄 | `{"ok": true, "count": <總筆數>}` |
| 讀取記錄 | `{"ok": true, "items": [...], "stats": {...}}` |
| 失敗 | `{"ok": false, "error": "<錯誤代碼>", "message": "..."}` |

### 統計定義

- **總記錄數**：`Sheet1` 資料列數（不含表頭）
- **待改善件數**：狀態欄位為 `待改善` 的筆數
- **高嚴重度件數**：`severity = 高` 且狀態為 `待改善` 的筆數

## 四、限制與錯誤

### 技術限制

| 限制 | 說明 |
|---|---|
| 後端為 Google Apps Script | 無法自訂 HTTP 狀態碼，一律回 200；錯誤以 `ok: false` 表達 |
| GAS 的 POST 轉址不帶 CORS 標頭 | 前端可能讀不到 POST 的回應。**對策**：送出後以 GET 重新讀取筆數作為客觀佐證（沿用履歷網站已驗證的做法） |
| 無身分驗證 | 知道網址的人都能寫入。**在頁面與 README 明確標示**，並建議僅在課堂展示使用 |
| GAS 執行時間限制 | 單次 6 分鐘上限，一般請求遠低於此 |
| Sheets 容量 | 遠超本作業需求 |

### 錯誤處理對照

| 情境 | 後端回應 | 前端行為 |
|---|---|---|
| 必填欄位缺漏 | `{"ok": false, "error": "VALIDATION"}` | 標示對應欄位、阻止送出 |
| 欄位超過長度 | 同上 | 顯示字數上限提示 |
| 試算表未設定／找不到分頁 | `{"ok": false, "error": "SHEET_NOT_READY"}` | 顯示「後端尚未完成設定，請聯絡管理者」 |
| GAS 執行例外 | `{"ok": false, "error": "INTERNAL"}` | 顯示「儲存失敗，請重試」並保留已填內容 |
| 網路失敗 | （前端例外） | 同上，且不清空表單 |

## 五、驗收條件

每一項都要能實際操作觀察。**驗收方式**：Chrome DevTools Protocol 手機模擬（390×844）
實際操作線上頁面，非人工目測；驗收日期 2026-10-28。

- [x] **A1** 用手機開啟網址，表單可正常填寫，無橫向捲動
      → `clientWidth=390 / scrollWidth=390`
- [x] **A2** 送出合法資料後，頁面顯示成功訊息，且 Google Sheets 新增一列，欄位內容與輸入一致
      → 回應「已新增一筆記錄（目前共 N 筆）。資料已寫入 Google Sheets。」
- [x] **A3** 連續送出 3 筆，3 筆都成功落地
      → 統計總數逐筆 +1，逐筆以 `?action=list` 讀回確認
- [x] **A4** 缺必填欄位時無法送出，且畫面標示是哪一個欄位
      → 6 項必填全部標示紅字並列出原因
- [x] **A5** 缺失描述超過 500 字時被擋下並提示
      → 模擬真人輸入 600 字，實際保留 500 字；直呼 API 送 501 字亦回 `VALIDATION`（後端縱深防禦）
- [x] **A6** 重新整理頁面後，「最近記錄」列表包含剛才送出的資料
      → 列表第一筆即為新記錄
- [x] **A7** 統計數字（總數／待改善／高嚴重度）與 Sheets 實際內容相符
      → 總記錄／待改善／高嚴重度未改善與試算表內容一致
- [x] **A8** 關閉網路後送出，出現錯誤提示且已填內容不遺失
      → 顯示「送出失敗…已填內容保留」，描述欄位內容仍在
- [x] **A9** 網址在無痕視窗可開啟（代表是公開可存取，非本機）
      → 匿名請求 HTTP 200、repo public、Pages public
- [x] **A10** 頁面載入時若後端未設定，顯示明確的錯誤訊息而非白畫面
      → 阻擋後端網域後顯示「後端未就緒」與具體排查指引
- [x] **A11** 逾期記錄標示正確：只有「待改善」且期限已過的記錄顯示「已逾期 N 天」
      → 期限 2026-10-25 的記錄顯示「已逾期 3 天」；今日／未來期限與「已改善」皆不標示
      （日期判斷另以 6 項單元測試驗證邊界）

> 後端另有 45 項本機邏輯測試（`gas/_test_harness.cjs`），涵蓋驗證、錯誤處理、統計、
> 排序、日期正規化與一次性資料重建。

## 七、已定案的設計決策

以下每一項都在實作前定案，實作與驗收皆照此執行。

| # | 決策 | 理由 |
|---|---|---|
| 1 | **不做登入、不做照片上傳** | 驗證服務與檔案上傳會超出本次工期；先把「現場記錄 → 資料落地 → 即時統計」這條主線做扎實。已列為未來延伸。 |
| 2 | **檢查項目採 12 項職安衛通用分類** | 涵蓋墜落、感電、物體飛落、機械、火災爆炸、缺氧中毒、PPE、警示、動線、衛生等現場最常見的危害類型。要調整只需改 `app.js` 的 `CONFIG.checkItems`（後端只驗長度，不綁清單）。 |
| 3 | **維持 7 個欄位** | 承包商、缺失編號、複查日期列為未來延伸；欄位越少，現場填寫越快，這是本工具的核心價值。 |
| 4 | **工地名稱自由輸入 + 自動累積建議** | 不做固定下拉：真實工地會變動，硬編清單會過期。改為把使用者實際填過的名稱自動加進 `datalist`，用越久越好填。 |
| 5 | **全面匿名化** | 範例、測試與示範資料一律使用「示範工地 A／B／C」「示範人員」，**不使用任何真實公司或專案名稱**。頁面公開且無驗證，避免被誤讀為真實工地的缺失紀錄。頁尾亦加註「本頁為課程作業示範，資料皆為虛構」。 |
| 6 | **一次性資料重建端點** | 測試資料需要清除，但公開端點不能有「任意清空資料」的能力。因此做成需 `confirm=RESET` 且僅能執行一次的維護指令。 |

> 上述決策若日後要變更，請同步更新本文件與 `README.md`，並在兩邊的變更紀錄各留一筆。
